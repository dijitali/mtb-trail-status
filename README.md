# MTB Trail Status

A trail map for mountain bike parks: difficulty grades, open/closed status, elevation profiles, entrances and other places, and offline viewing. It works for any park. Each park is a folder of plain files that a club can edit, and this repository ships with [Maraetai Forest](parks/maraetai) as its example.

Trails are drawn on an OpenStreetMap base map in their grade colour. Closed trails keep that colour but are drawn faded and dashed, and one-way trails carry direction arrows. Trail names sit above everything else on the map.

Clicking a trail opens its status, grade and comments, plus an elevation profile. The profile shows length, total climb and descent, the steepest 100 m, and a strip shading each 50 m section by steepness. One-way trails are profiled in the riding direction. Hovering or tapping the profile shows a marker at that spot on the map.

Places such as entrances, car parks and shelters appear as badges on the map and in a list in the side panel. Each one has a popup with a link for directions.

## Parks

Each park lives in its own folder under `parks/`:

```
parks/maraetai/
  park.json        settings: title, map rotation, grading system, elevation data…
  trails.csv       the trails and their status, edited by the club
  pois.csv         entrances and other places (optional)
  trails.geojson   cached trail lines and elevation profiles, generated by a script
```

The build serves one park, chosen with the `PARK` environment variable. It defaults to `config.park` in `package.json`, which is `maraetai` here.

```sh
PARK=maraetai npm run dev
PARK=maraetai npm run build
```

### Adding a park

1. Create `parks/<name>/park.json`. Only `title` is required:

   ```json
   { "title": "Example Bike Park", "grading": "uk" }
   ```

2. Add `parks/<name>/trails.csv` (see below). Add `pois.csv` too if you want places on the map.
3. Run `PARK=<name> npm run fetch-geometry` to download each trail's line and elevation profile.
4. Run `npm test`. It checks every park folder: valid settings, known grades, and cached geometry for every trail.
5. Build with `PARK=<name> npm run build` and host the `dist/` folder anywhere static.

### Updating trail status

`trails.csv` lists one trail per row:

```csv
name,osmId,status,comments,grade
Horse Track,434871453,Open,Watch out for horses!,2
Yippi Ki Yay,434871466,Closed,Closed for logging until 1970-01-01,4
```

| Field      | Meaning |
| ---------- | ------- |
| `name`     | Display name for the trail |
| `osmId`    | The OpenStreetMap way ID for the trail |
| `status`   | `Open` or `Closed` (anything else is shown as-is with a grey badge) |
| `comments` | Free text shown in the trail list and popup |
| `grade`    | A grade from the park's grading system, such as `3` for the NZ grades or `red` for UK grades |

Changing a status or comment is a one-line edit. In a built site the file is at `park/trails.csv`, so a club can edit it on the server without rebuilding. Header names and grade values are matched case-insensitively.

### Places

`pois.csv` lists entrances and other points of interest:

```csv
name,type,lat,lon,description
Rewa Road entrance,entrance,-36.88490,175.04038,Gate at the end of Rewa Road.
Shelter,shelter,-36.90770,175.04661,Shipping container shelter near the Pukekawa trig.
```

`lat` and `lon` are decimal degrees. These are the supported types:

| Type | Also accepts |
| --- | --- |
| `entrance` | trailhead, access |
| `parking` | car park, carpark |
| `shelter` | hut, container |
| `toilet` | toilets, wc |
| `water` | drinking water, tap |
| `bike-wash` | bike wash, wash |
| `info` | information, map board |
| `first-aid` | first aid, aed, defibrillator |
| `viewpoint` | lookout, view |
| `other` | any other type is shown as a general place, with a warning |

### Trail geometry and elevation

The app reads trail lines and profiles from `trails.geojson` instead of querying OpenStreetMap or an elevation service on every visit. This keeps it fast, avoids rate limits and makes offline use possible. If a trail is in the CSV but not the cache, the app fetches its line live from the OSM API and shows a warning. It has no profile until the script is run.

```sh
npm run fetch-geometry                 # fetch anything missing for the selected park
npm run fetch-geometry -- --all        # re-fetch every trail and profile (picks up OSM edits)
npm run fetch-geometry -- --profiles   # re-fetch every elevation profile only
npm run check-geometry                 # fail if any park is missing anything (used by CI)
```

Elevations are sampled every 10 m along each trail from an [OpenTopoData](https://www.opentopodata.org) dataset. The public API allows 1 request a second and 1,000 a day, which is plenty for occasional updates.

Trail data is © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright). Each park's elevation source is credited in its `park.json`. Maraetai uses the LINZ 8 m Digital Elevation Model, [CC BY 4.0](https://data.linz.govt.nz/layer/51768-nz-8m-digital-elevation-model-2012/).

### park.json reference

Everything except `title` is optional. A mistake fails the build with a list of every problem found.

| Setting | Default | Meaning |
| --- | --- | --- |
| `title` | required | Page and header title |
| `shortName` | `title` | Name under the home-screen icon when installed |
| `description` | generic | Page description |
| `themeColor` | `#1b5e20` | Header and accent colour |
| `map.rotation` | `0` | View rotation in degrees, to match a printed map |
| `map.center`, `map.zoom` | fit to data | Fixed starting view as `[lon, lat]` and zoom. Leave `center` null to fit the trails and places. |
| `map.padding` | `[60, 90, 60, 90]` | Margin in pixels around the data when fitting the view; halved on phones |
| `map.tileUrl` | OpenStreetMap | Any XYZ tile template with `{z}`, `{x}` and `{y}` |
| `grading` | `"nz"` | A preset name, or an object (see below) |
| `elevation.dataset` | `srtm30m` | OpenTopoData dataset, such as `nzdem8m` for New Zealand or `eudem25m` for Europe. Set `"elevation": false` to turn profiles off. |
| `elevation.attribution` | SRTM credit | Credit line for the elevation data |
| `offline.minZoom` / `maxZoom` / `maxTiles` | `12` / `16` / `600` | Zoom range and tile budget for "Save map for offline" |
| `data.trails` / `pois` / `geometry` | `trails.csv` / `pois.csv` / `trails.geojson` | File names inside the park folder |

### Grading systems

There are three presets:

| Preset | Grades |
| --- | --- |
| `nz` | New Zealand MTB track grades `1` Easiest to `6` Extreme |
| `imba` | IMBA ratings `white`, `green`, `blue`, `black`, `double-black` |
| `uk` | UK trail centre colours `green`, `blue`, `red`, `black`, `orange` |

To rename a grade, recolour one or add your own, combine a preset with `grades`. Keys are the values used in `trails.csv`:

```json
"grading": {
  "preset": "uk",
  "grades": {
    "orange": { "name": "Jump line" },
    "skills": { "name": "Skills area", "color": "#888888" }
  }
}
```

Leave out `preset` to define a grading system from scratch. Each grade needs a `name` and a hex `color`, and can have a `label` shown before the name, as in "Grade 3 · Intermediate".

## Offline viewing

The site is a Progressive Web App. A service worker precaches the app and keeps copies of the park's data files and any map tiles that have been viewed. Park data is fetched network-first, so a status change appears as soon as the device is online. **Save map for offline** prefetches every tile covering the trails and places between the configured zoom levels, so the whole map is available before the rider loses signal.

## Development

```sh
npm install
npm run dev        # local dev server for the selected park
npm test           # unit tests, plus checks on every park folder
npm run build      # production build in dist/
npm run preview    # serve the production build
```

Hosting under a sub-path, for example GitHub Pages at `/mtb-trail-status/`, needs `BASE_PATH=/mtb-trail-status/ npm run build`.

### Project layout

```
parks/<park>/               one folder per park (see above)
scripts/park.mjs            finds and validates the selected park
scripts/vite-plugin-park.mjs  bundles the park's settings and publishes its data files
scripts/fetch-geometry.mjs  refreshes a park's trails.geojson
src/park/                   park settings defaults, validation and grading presets
src/lib/                    pure data code (CSV, places, OSM, elevation, profiles, tiles, arrows, colour)
src/map/                    OpenLayers map, trail and place styles, popup
src/ui/                     side panel and elevation profile chart
src/data.js                 loads a park's trails, places and geometry
src/offline.js              service worker registration and tile prefetch
test/                       unit tests and park folder checks
```
